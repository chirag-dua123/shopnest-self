### 🔴 Critical Security Vulnerabilities

  1. Trusting Client Data for Pricing (Critical)
      • Issue: In orderController.js, you extract totalPrice directly from req.body (const { totalPrice } = req.body;). A malicious user can intercept the
      request, change totalPrice: 1000 to totalPrice: 1, and the backend will blindly save the order at $1.
      • Fix: The backend must calculate the totalPrice server-side by fetching the actual product prices from the database for each item in orderItems,
      completely ignoring any price sent by the client.
  2. NoSQL Injection Vulnerabilities
      • Issue: Controllers like authController.js take inputs directly from req.body (e.g., User.findOne({ email: req.body.email })). If an attacker sends a
      JSON object instead of a string, like {"email": {"$gt": ""}}, it can manipulate the database query, potentially bypassing authentication or exposing
      data.
      • Fix: Use a package like express-mongo-sanitize to remove $, and enforce strict schema casting on incoming data.
  3. No Brute Force Protection / Rate Limiting
      • Issue: Your authentication endpoints (/login, /register, /verify-otp) have no rate limits. An attacker can use automated scripts to infinitely guess
      passwords or OTPs without being blocked.
      • Fix: Implement express-rate-limit (specifically on auth and OTP routes) to limit the number of requests per IP address in a given timeframe.
  4. Missing CORS Configuration
      • Issue: cors is in your package.json, but it is not initialized in index.js. Depending on how you deploy, your frontend will either be completely
      blocked from making requests to the backend, or if you just add app.use(cors()), it will accept requests from any malicious website (CSRF
      vulnerability).
      • Fix: Configure cors to strictly allow only your frontend's specific origin domain.
  5. Unbounded Database Queries (DoS Risk)
      • Issue: Your getProducts controller runs Product.find({}). If your database grows to 10,000 products, this will try to load all of them into memory at
      once, crashing your server or significantly slowing it down (Denial of Service).
      • Fix: Implement server-side pagination using Mongoose's .limit() and .skip() along with query parameters like ?page=1&limit=10.
  6. Race Conditions in Inventory Management
      • Issue: When an order is placed, if two people buy the last remaining item at the exact same millisecond, both orders might go through because the
      stock check and stock deduction are not atomic.
      • Fix: Use MongoDB atomic operators like $inc: { stock: -quantity } and check if the result falls below 0, or use MongoDB transactions.

  ### 🟡 Missing Essential E-commerce Features

  1. Payment Gateway Integration
      • You have razorpay in your package.json, but no actual endpoints to create a Razorpay order ID or a webhook endpoint to cryptographically verify that
      a payment was actually successful before marking the order as "Paid".
  2. Search, Filtering, and Sorting
      • getProducts currently just returns a dump of all items. To be functional, you need query support: searching by keyword (regex), filtering by
      categories/price boundaries, and sorting (price low-high, newest, etc.).
  3. Image Upload Service
      • You have multer and cloudinary installed, but no endpoint to actually upload product images securely. We need an admin-only endpoint to upload photos
      and return the Cloudinary URL.
  4. Order State Management (Admin & User)
      • Users can create orders, but there are no endpoints for them to view their "Order History" or for Admins to update order statuses (e.g., Processing -
      > Shipped -> Delivered).
  5. Forgot Password Flow
      • While you have OTP for registration, there is no flow for a user to request a password reset link/OTP if they forget their credentials.
